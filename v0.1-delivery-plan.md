V0.1 的成功定义不是“页面能填写”，而是固定测试账号能够进入一份结构化简历，编辑、显隐、排序和刷新恢复后内容保持一致；任何已显示“已保存”的内容都能从服务器版本中读回。原型仍只用于视觉和流程参考，正式代码放入 `platform/`。

## 2. 范围与发布边界

### 2.1 必须交付

- 固定测试账号和固定 `resumeId` 的开发身份适配器；身份只由服务端配置注入，浏览器不能提交或切换 `userId`。
- 单一编辑器入口及固定测试简历初始化；不交付登录、工作台或简历 CRUD。
- 编辑器：基本信息、求职意向、概要、教育、工作、项目、实习、校园、技能证书、奖项、自我评价和自定义模块。
- 条目新增、复制、删除、折叠；模块新增、显隐、拖拽及键盘排序；隐藏不删除数据。
- A4 实时预览、多页反馈、缩放及面板收起；V0.1 不承诺生产 PDF。
- 单一 Resume Schema、完整快照保存、revision CAS、不可变版本、幂等回执。
- IndexedDB 草稿、刷新恢复、保存失败状态、手动重试、离开保护、冲突保全和另存副本。
- 当前会话撤销/重做；版本恢复 API 内核存在，完整历史浏览可后置。
- 双账户越权、保存竞态、键盘流程和边界文档测试。

### 2.2 明确不做

不建立注册登录、工作台、简历 CRUD、AI Provider、额度账本、Worker、对象存储、支付、分享或 PDF Chromium 集群；不为未来版本显示伪入口。V0.1 只允许受控本地或内网测试，不得直接作为公开多用户版本发布。可以保留清晰模块端口与数据库迁移空间，但不得提前实现空壳微服务或业务表。

## 5. 保存协议的唯一结论

客户端每次编辑立即更新工作副本和预览，并提高 `localSeq`；本地备份与云端保存分别报告。上传使用完整快照，不使用网络 JSON Patch。一个标签页同一时刻只有一个请求，发送前冻结：

```text
{ resumeId, idempotencyKey, baseRevision, clientSeq, document }
```

服务器在同一事务中完成幂等声明、所有权和 revision CAS、当前文档更新、不可变版本插入及回执提交。响应丢失时原样重发，不生成新键。ACK 只确认 `acknowledgedSeq` 和远端基线，绝不能把响应携带的旧文档重新写入当前编辑 Store。

412 后暂停自动上传，保留 base/local/remote；首期不自动合并复杂数组。用户可以逐项合并、明确采用远端，或将本地分支另存为新简历。不得提供隐藏的 force overwrite。

| SPIKE-02 | 服务端已提交但响应丢失   | 通过：同 key/body/baseRevision 重放            | 真实代理断连和回执 TTL                |
| SPIKE-03 | 两写共享同一 revision    | 通过：一个 revision+1，一个 412                | UI 三方差异和另存副本                 |
| SPIKE-04 | 同 key 同 body 并发/重放 | 通过：返回同一 receipt，只建一个版本           | 请求处理中超时和进程重启              |
| SPIKE-05 | 同 key 偷换 body         | 通过：409，无新写入                            | HTTP canonical body/header 绑定       |
| SPIKE-06 | CAS 后版本插入前故障     | 通过：文档、版本和幂等声明全部回滚，可原键重试 | 数据库断连/故障代理测试               |
| SPIKE-07 | 其他账户猜 resumeId      | 通过：统一 404，无写入                         | RLS 与完整 API 双层测试               |
| SPIKE-08 | IndexedDB 写失败         | 通过：本地备份降级独立显示，云端可救援         | 真实浏览器 quota/private mode         |
| SPIKE-09 | 开发身份被切换           | 通过：拒绝恢复原身份草稿上传                   | 公开测试前用 Better Auth 真实会话重跑 |
| SPIKE-10 | 数据库角色隔离           | 自动验证                                       | 初始生产迁移后的表级权限/RLS          |

只有“当前结果”和对应正式实现补充都通过，才能把保存能力标记为生产已验证。内存协调器测试不能代替 PostgreSQL，PostgreSQL实验也不能代替浏览器崩溃恢复。

## 7. V0.1 阻断性验收

- 任一已显示“已保存”的内容无法按 receipt/revision 读回：阻断。
- ACK 覆盖较新的本地输入、冲突静默采用任一分支、换账户上传旧草稿：阻断。
- 隐藏/排序删除内容或重新生成 ID：阻断。
- 其他账户可读取 resume/version：阻断。
- IndexedDB 不可用却仍显示“本地已备份”：阻断。
- 边界文档输入明显卡顿、预览裁切/消失：阻断。
- 必要自动化测试未运行、被跳过或只用 mock 成功：阻断。
