# V0.2 安全脱敏与运行告警手册

日期：2026/10/9  
适用范围：V0.2 本地代码候选版；不代表中国大陆公开发布就绪

## 1. 安全日志合同

运行告警只允许以下字段：`schemaVersion`、`alertId`、`occurredAt`、`environment`、`release`、`severity`、`resourceType`、`failureCode`、`runbookId`、`recipient`，以及可选的非敏感 `traceId`。

禁止写入密码、Cookie、Session、Token、验证/重置 URL、邮箱、简历正文、邮件正文、数据库连接串、SQL 文本或绑定参数。告警代码不接收原始异常对象；接收器失败时只把同一白名单事件送到标准错误流。

当前本地接收路径为 `invoking-operator-stderr`，实际接收人是启动 Web 或运维 CLI 的操作者。测试使用进程内接收器验证送达。staging/production 在配置真实值班通道和接收人之前必须保持阻断，不得把标准错误流表述为 7×24 告警。

## 2. 响应头边界

Next.js 对全部路由发送 CSP、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY` 和最小 Permissions Policy。生产 CSP 不允许 `unsafe-eval`，连接只允许同源；开发模式仅为热更新增加 WebSocket 和 `unsafe-eval`。

HSTS 必须由已验收的 HTTPS 入口代理注入。当前本地 HTTP 候选版不发送 HSTS，避免把未验收的 TLS 拓扑写死到应用构建中。

## 3. 告警处置

### OPS-AUTH-MAIL-01

1. 停止扩大邮件重试，记录 `alertId`、环境、版本和发生时间。
2. 检查邮件发送器连通性、超时和供应商状态；不得复制邮件正文、地址、Token 或验证链接到工单。
3. 恢复后用合成账户验证发送和安全重试；公开环境必须另有真实供应商与收件证据。

### OPS-PRIVACY-CLEANUP-01

1. 暂停对应清理任务，不手工删除数据库行。
2. 核对删除清单水位、确认标记、运行环境和专用角色；只记录计数与最老超期秒数。
3. 在 `resume_opt_test` 先执行 dry-run，再按原幂等流程重跑；若水位或哈希不一致，保持失败关闭。

### OPS-DB-RESTORE-01

1. 隔离失败演练，不删除源备份或修改生产数据库。
2. 核对测试库、PostgreSQL 工具版本和 Docker 容器绑定；禁止把容器 ID、连接串或密码写入证据。
3. 仅在随机隔离 schema 与合成数据上重跑，要求归档 hash、行数/hash、RLS、授权、删除重放和旧认证撤销全部通过。
4. 本地 `pg_dump/pg_restore` 不替代加密备份、WAL/PITR、跨主机恢复或真实 RPO/RTO。

## 4. 依赖审计

联网审计使用 npm 官方审计端点：

```powershell
pnpm audit --prod --audit-level=high --registry=https://registry.npmjs.org
```

镜像源缺少审计端点时不能记为通过。高危或严重公告必须升级、移除或证明不进入可利用运行路径；人工判定应记录依赖路径、适用条件和残余风险，不得静默忽略。

## 5. 回滚与外部阻断

出现安全头兼容问题时，先停止受影响入口并回滚对应应用版本；不得关闭必要的同源、CSRF、RLS、CAS 或脱敏保护。当前不接入 Replay、第三方分析或新监控平台。

真实值班通道、收件人轮值、HTTPS/HSTS、邮件供应商、加密备份、PITR 和跨主机恢复属于 V02-033 外部验收项；这些证据缺失时只能称为本地代码候选版。
