# V0.2 安全脱敏与运行告警验收记录

日期：2026/10/9

任务：V02-031

## 结论

本地代码候选版验收通过：合成秘密 canary 未进入告警或外抛错误，邮件、隐私清理和备份恢复三类失败均有注入测试；本地实际告警接收路径为启动进程的操作者标准错误流。生产依赖已知可利用高危和严重漏洞为 0。

该结论不包含 staging/production 真实值班通道、真实邮件、HTTPS/HSTS、PITR 或公开发布就绪。

## 安全头与客户端边界

- 全路由 CSP 及浏览器安全头单元测试通过。
- Next.js 生产构建通过；原生 Chrome 读取真实响应，确认 CSP、`nosniff`、`DENY` 与 `no-referrer`，页面控制台 CSP 违规为 0。
- 生产 CSP 不含 `unsafe-eval`，不开放任意外部域名。
- dependency-cruiser 的客户端导入运维告警模块负例被 `client-no-server` 规则拒绝；完整边界检查 147 个模块、213 条依赖无违规。

## 脱敏与告警送达

- 三类失败注入分别使用只存在于异常消息中的合成 canary；接收事件和安全外抛错误均未出现 canary。
- 认证 PostgreSQL 集成测试注入验证邮件失败、超时和密码重置邮件失败，三次 `AUTH_MAIL_DELIVERY_FAILED` 均送达进程内接收器，事件不含 canary 或邮箱。
- 原生恢复首次在未配置 Docker 原生工具模式时真实失败，`BACKUP_RESTORE_FAILED` 已送达 `invoking-operator-stderr`；输出只含白名单字段和安全错误文案。
- 随后临时绑定当前本地 PostgreSQL 容器重跑成功：PostgreSQL 16.15 自定义归档 88,982 字节，备份约 518.92 ms，恢复与删除重放约 841.93 ms；归档 hash、行数/hash、RLS、授权、删除重放、旧认证撤销和幂等重放全部通过。
- 数据库无需新增迁移；现有审计与删除清理继续只保留既定最小元数据。

## 依赖审查

联网审计使用 npm 官方端点；默认 npmmirror 不提供审计接口，因此其失败未记为通过。

- Next.js 从 16.3.5 精确升级到 16.3.8，消除命中的严重和高危 Next.js 公告。
- 通过 pnpm 覆盖把 `sharp` 固定为 0.35.5、`source-map-js` 固定为 1.2.2，消除对应两个高危公告。
- `pnpm audit --prod --audit-level=high --registry=https://registry.npmjs.org` 结果：严重 0、高危 0、中危 1。
- 唯一残余中危为 Better Auth 可选迁移工具链 `drizzle-kit -> @esbuild-kit -> esbuild@0.18.20` 的开发服务器 CORS 公告。项目生产服务不启动 esbuild serve，生产 Next.js 运行路径不使用该开发服务器；因此不构成当前可利用高危阻断。后续升级 Better Auth/迁移工具链时继续移除该残余项。
